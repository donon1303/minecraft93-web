# Ежедневный GitHub-бот для minecraft93-web

## Что делает бот

- Запускается ежедневно в 06:00 по Екатеринбургу (01:00 UTC).
- По расписанию или вручную выбирает случайное число от 1 до 15.
- Просит OpenAI предложить улучшения основной страницы `frontend/93-server (5).html`.
- Применяет только небольшие текстовые/HTML/CSS-изменения до первого блока JavaScript.
- Проверяет обязательные разделы страницы, адрес сервера, число скриптов и `git diff --check`.
- Создаёт отдельный коммит для каждого прошедшего проверку изменения и отправляет его в `main`.
- Если безопасных изменений меньше выбранного количества, публикует меньше коммитов, а не создаёт фиктивные.

## Настройка на GitHub (русский интерфейс)

1. Открой репозиторий `donon1303/minecraft93-web`.
2. Перейди в **Настройки → Секреты и переменные → Действия**. Прямая ссылка: <https://github.com/donon1303/minecraft93-web/settings/secrets/actions>.
3. Нажми **Создать секрет репозитория**.
4. В поле **Имя** укажи `OPENAI_API_KEY`.
5. В поле **Секрет** вставь API-ключ из <https://platform.openai.com/api-keys> и сохрани.
6. Убедись, что GitHub Actions разрешено запускать рабочие процессы. Вкладка называется **Действия**.
7. Добавь в репозиторий файлы из этого архива, сохранив пути, или скопируй изменения в соответствующие файлы.
8. Открой **Действия**, слева выбери **Daily AI Developer**, нажми **Запустить рабочий процесс**, выбери `main` и подтверди запуск.
9. Открой запуск и проверь журнал шага **Создать улучшения и отдельные коммиты**.

## Важные замечания

- OpenAI API оплачивается отдельно от подписки ChatGPT; ежедневный запуск может создавать расходы. Ограничь бюджет API в панели OpenAI и проверяй использование.
- Это автоматизация с ИИ, поэтому перед включением ежедневного расписания рекомендуется сначала проверить ручной запуск.
- Бот намеренно не меняет JavaScript, адрес сервера и ссылки сообщества. Проверки не заменяют полноценное тестирование в браузере.
- GitHub Actions может начать выполнение позже запланированного времени.
- Для публикации используется встроенный `GITHUB_TOKEN` с разрешением `contents: write`; отдельный GitHub-токен не требуется.
